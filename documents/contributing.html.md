There is a lot remaining to be done in the AkashaCMS project.

This project began in 2014 (or earlier) and has remained in the hands of one guy, who hasn't had the time to fulfill the vision for this software.  There's a lot of rough edges, incomplete functionality, missing functionality, experiments that should have been removed, and best practices to implement.

The areas where the AkashaCMS project needs help are:

* **Issues and Planning**: The [AkashaRender issue queue](https://github.com/akashacms/akasharender/issues) contains most of the issues for both `akasharender` and the plugins.  This is a convenience so there's one place for project management.  Overall tracking of milestones like the 0.9, 0.10, or 0.11 release trains is handled in this issue queue.
* **Documentation**: Each package contains its own documentation.  In most cases that documentation is published via the `akashacms.com` website, which is handled in the `akashacms-website` repository.
* **Testing**: Each package strives to contain tests for its functionality.
* **Coding**: New features, bug fixes.
* **Internationalization**: No attempt was made to internationalize or localize anything about AkashaCMS.
* **Security**: Other than following common-sense best practices, security has received very little attention.
* **Performance**: There is a performance testing repository, that needs a lot of work to straighten it out into a tool for proper performance measurements and detecting performance regressions.

## Resources for understanding AkashaCMS

Start with the AkashaCMS website - https://akashacms.com - and read everything.

In the AkashaRender repository, there is a "LLM Wiki" that contains a lot of architectural documentation most of which is autogenerated by AI systems.  To use this, start an AI agent program like OpenCode, Pi, Codex, while your terminal is in the AkashaRender repository.

Simply ask questions, and the AI agent has already been instructed to start with documentation in the wiki.

## Contribution process

Set up a [development environment](/howto/development.html)

Pick out either an existing issue or develop your own idea of how to improve something in the AkashaCMS ecosystem.

If there is no issue in any issue queue, start one, outlining your plan.  We'll be able to converse over best practices, implementation, and the like.

In your cloned repository, start with a new branch:

```shell
git checkout -b new-branch-name
```

When your contribution is ready, make sure it contains:

* Required source code changes
* New tests, or changes to tests
* New documentation, or changes to documentation

Commit and push all changes to GitHub

```shell
git commit -m 'Commit message' -a
git push -u origin new-branch-name
```

When pushing to the repository, GitHub should give you a URL to click on to create a pull request.  Do so.
